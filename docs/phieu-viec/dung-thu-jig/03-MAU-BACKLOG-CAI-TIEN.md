# Mẫu backlog cải tiến JIG (tổng hợp sau dùng thử)

Mục đích: gom phản hồi từ `02-MAU-BIEN-BAN-DUNG-THU.md` thành danh sách cải tiến **có thứ tự ưu tiên**, chờ người dùng/trưởng nhóm **chốt**. OMP/Muse không tự chốt mục nào.

## Thang ưu tiên (đề xuất để user chốt)

- **P0 — chặn dùng**: lỗi/cản trở khiến không hoàn thành được việc thật trong lượt dùng.
- **P1 — cần sớm**: dùng được nhưng tốn thời gian / khó hiểu / dễ sai, làm giảm giá trị rõ rệt.
- **P2 — cải thiện**: trải nghiệm, tiện thêm; không ảnh hưởng kết quả nghiệp vụ.

## Bảng backlog

| # | Mục | Loại | Mô tả + cách tái hiện | Ai nêu | Ảnh hưởng | Ưu tiên đề xuất | User chốt |
|---|---|---|---|---|---|---|---|
| B1 | | | | | | P0 / P1 / P2 | (chưa chốt) |
| B2 | | | | | | | (chưa chốt) |
| B3 | | | | | | | (chưa chốt) |

Ghi chú loại: `lỗi` = sai/không chạy; `thiếu` = chức năng cần mà chưa có; `cải tiến` = muốn tốt hơn; `giao diện` = câu chữ/cách hiển thị.

## Sau khi chốt

- Mục `P0`/`P1` được chuyển thành vé sửa/bổ sung theo quy trình phiếu việc (Muse phát hành, có tiêu chí ĐẠT đo được). Việc phát hành vé **không** nằm trong vé J3.
- Giữ nguyên bảng này làm vết; không xóa mục đã xử lý — ghi kết quả xử lý vào cột "User chốt" khi có.
